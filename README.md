# LegendServer

**某款移动端游戏的本地离线服务端** — 让已停运的游戏在完全离线状态下运行。

## 项目简介

**某游戏**是一款基于 **Unity IL2CPP** 的客户端。官方服务端停运后，本项目通过逆向分析其网络协议、
主数据格式与资源加载路径，实现了一套**本地离线服务端**：

- 客户端通过 BepInEx 插件把 API 与 CDN 请求重定向到本机
- 服务端复现官方的请求/响应契约，并用**玩家自己客户端里的资源文件**作答
- 全程不联网，仅监听 `127.0.0.1`

**本仓库只包含我们编写的代码。** 游戏客户端、主数据、美术与音频等一切原始资产均由
使用者**自备**，详见 [前提条件](#前提条件)。

## 特性

- ✅ **纯标准库实现** — 只用 Node 内置模块，无第三方依赖
- ✅ **完整端点覆盖** — 175 个权威端点全部有响应，无「未实现」占位
- ✅ **状态机而非回放** — 读入参、改状态、产出，不是把抓包原样返回
- ✅ **属性系统全量对齐** — 9 个养成系统（等级/突破/好感/职业/天命/训练板/记忆之书/大师位阶/传说强化）逐字段复算
- ✅ **资源本地化** — 解析客户端自己的资源索引，按需回发
- ✅ **六套自动化测试** — 契约审计 / 行为 / 数量守恒 / 有数据态 / 并发 / 业务不变量

## 前提条件

**你必须已经拥有该游戏的客户端。** 本仓库不提供、也不包含：

| 内容 | 说明 |
|---|---|
| 游戏本体 | 主程序与 `*_Data/` 目录 |
| 游戏资源 | AssetBundle、图片、音频、文本 |
| 主数据 | `master/*.zip`、各类 master 表与 `load_master_data` 的 JSON |
| 资源清单 | `fileInfo`、索引文件 |
| 存档数据 | 任何玩家记录 |
| 抓包契约 | `contracts/` 下的真实响应样本 |

把这些放在下面的目录结构里，服务端会自动使用：

```
<工作目录>/
├── client/                  # 你的游戏客户端（原样放这里，目录内含 *_Data/）
├── game_data/               # 由你自己的客户端/抓包生成的数据
│   ├── masterdata/          #   解包后的 master CSV（410 张表）
│   ├── masterdata.zip       #   master 包（服务端下发给客户端）
│   └── capture/             #   你自己抓的真实响应样本
└── server/                  # 本仓库的代码
    ├── main.mjs
    ├── state/               #   存档（首次运行自动生成）
    └── contracts/           #   契约样本（你自备）
```

## 快速开始

需要 **Node.js 18+**，无需安装依赖：

```cmd
cd <工作目录>\server
node main.mjs
```

Windows 上也可以用：

```cmd
restart-server.cmd        :: 杀掉旧进程 → 等端口释放 → 启动一个 detached 实例
```

服务端只监听 `127.0.0.1:18100`，启动日志会输出监听地址与存档信息。

## 工作方式

```
┌──────────────┐   HTTP (被重定向)   ┌──────────────┐
│   游戏客户端  │ ──────────────────> │  本地服务端   │
│              │                     │  main.mjs    │
└──────┬───────┘                     └──────┬───────┘
       │ BepInEx 插件改写                  │ 读取
       │ （插件不在本仓库）                │ 客户端自带的资源
       ▼                                  ▼
  127.0.0.1:18100                  client/**/resource/**
```

| 路径 | 作用 |
|---|---|
| `/v1/**` | 业务接口，复现官方契约 |
| `/<platform>/fileInfo` | 资源清单（用于客户端差异比对） |
| `/master/<guid>.zip` | 主数据包 |
| `/gacha-info/*.html` | 内嵌 WebView 的静态页面 |

### 关键设计

- **资源不下发**：服务端只把客户端**自己已有的**文件按索引再发一次
- **契约优先**：每个端点的响应形状都对照真实抓包验证，而非凭字段名推测
- **数据驱动**：主数据、资源索引均从使用者本地客户端生成，仓库内不含任何资产
- **收口而非散落**：状态变更后的派生值（属性、战力、回执）在唯一出口统一重算

## 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `LEGECLOX_PORT` | `18100` | 监听端口 |
| `LEGECLOX_STATE` | `state/user.json` | 存档路径（测试用独立文件） |
| `LEGECLOX_REPLAY` | （空） | 回放模式：直接返回抓包原始响应 |
| `LEGECLOX_REPLAY_SEQ` | （空） | 顺序回放（按抓包运行目录） |
| `LEGECLOX_LATENCY_MS` | `150` | 模拟网络延迟（0 = 关闭） |
| `LEGECLOX_ORACLE_SPEED` | `720` | 「以时间为单位」玩法的加速倍率 |
| `LGSRV_CLIENT_DATA` | 自动探测 `client/*_Data` | 客户端数据目录 |
| `LGSRV_MASTERDATA` | `game_data/masterdata` | master CSV 目录 |

## 测试

```cmd
node run-tests.mjs            :: 起一个隔离实例（18199 + 独立存档），跑完即杀
```

| 套件 | 覆盖 |
|---|---|
| `audit.mjs` | 契约审计：字段名 / 类型 / 形状 / 静态 id，含三个静态检查 |
| `selftest.mjs` | 入参敏感性、状态持久化、响应结构 |
| `functest.mjs` | 功能级：副作用是否真的发生（数值、入库、标记） |
| `emissiontest.mjs` | 数量守恒（抽 10 必出 10） |
| `statetest.mjs` | 「有数据」状态下的读取一致性 |
| `contest.mjs` | 并发安全 |
| `invariants.mjs` | 业务不变量（总和 = 分项之和、id 不越界、无混型数组…） |
| `verify_status.mjs` / `verify_vs_live.mjs` | 面板属性逐字段复算 |

> 测试会 `__reset` 存档，**必须在隔离实例上跑**（`run-tests.mjs` 已内置），
> 否则会覆盖你正在玩的档。
